# 产品判断与反馈记录

## 2026-09-23 · 用户纠正：必须从参考中提炼并确定技术方案

- 用户原话：“小红书作者已经分享过skill+大模型的方案。我明白了，我让你看小红书素材，但没要求你把合适的技术方案也提炼出来，定技术方案。这点一定要做到，也要记到相关的工作记忆中去。”
- 本条是对研究流程的明确纠正：以后阅读参考时，除了记录内容和启发，还必须提炼可复用的技术方案，说明采用、暂不采用和验证边界，并写入项目记录；不能只停留在“可以借鉴”。
- 本阶段技术方案已确定为两层：
  1. **生产层：Skill + 多模态/编码大模型 + 生图模型。** Skill 固化输入检查、主体识别、角色风格规范、角色母版 JSON、分层/矢量资产约束、动作语义模板、结果检查和重试。大模型负责把一张照片与用户选择的感觉整理成角色资产规范，并生成/编排资产生产任务；Seedream 负责角色图和必要的参考图生成。Skill 是生产流程与约束，不是另一个生图模型。
  2. **运行层：本地角色资产 + 可复用 SVG/分层动作时间线。** 角色拆成身体、五官、手、道具和背景/桌面等可控部件；呼吸、眨眼、轻摆等通用动作直接复用；喝水、挥手、击掌等涉及接触的动作使用动作语义模板和角色接口重新适配。Electron 桌面端本地播放，单次动作完成后停在末帧；不让用户每次打开桌宠都依赖 Codex、联网大模型或实时生图。
- **唯一输入**：用户授权的一张真人照片 + 一个用户选择的感觉/风格（例如纸感、毛毡、像素、插画；首版只选择一种）。不要求用户提供三视图、动作参考或多张照片；照片质量不足时明确提示并允许重选。
- **确定的输出契约**：
  - `character-master`：透明角色母版、角色识别信息、风格参数、比例与锚点、部件清单、版本号；
  - `character-parts`：身体/脸/眼睛/手/配饰等可动画部件，统一画布、落点和层级；
  - `motion-library`：至少 6 个动作示例（待机呼吸、眨眼、挥手、喝水、击掌、睡觉），每个动作包含语义、时长、关键姿态、接触点、循环/单次标记和末帧；
  - `preview`：角色母版 + 动作示例的可操作预览，不自动覆盖当前桌宠；
  - `fallback`：资产不合格时保留角色静态图和可用的通用待机，不用随机生成图冒充动作。
- **采用依据**：`6a33dfbb` 明确提到把 SVG 动画制作中的经验整理成 Skill；`6a045a1a`、`6a9952b6`显示“角色素材/动画参考/提示词或文档→编码代理生成桌宠”的生产方式；现有项目已有本地 SVG 单次时间线，可作为运行层基线。上述参考没有证明所有细节都能自动化，因此仍需用第二个角色做复用验证。
- **暂不采用**：把 GIF 作为唯一技术方案（无法稳定换角色和控制末帧/接触点）；把整段图生视频作为日常运行方案（身份漂移、资源和联网成本）；让终端用户必须安装/使用 Codex；把作者评论中的“2分钟”“任何形象”“会对话”当作产品承诺。
- **本阶段验收顺序**：先用两张不同主体照片、同一套动作模板验证角色身份、手/道具接触、动作连续性、末帧静止和小尺寸辨识；通过后再扩展动作数量和复杂场景。用户尚未验收本方案，也未授权开始大规模资产生产。
