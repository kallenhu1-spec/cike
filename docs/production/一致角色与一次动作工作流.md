# 此刻：从喜欢的感觉，到一致角色，再到一次动作

## 2026-09-23 技术方案定案（待原型验收）

用户明确要求：参考阅读不能只记录灵感，必须提炼已经出现的 `Skill + 大模型` 技术路线并定下输入输出，再开始实现。本节是当前采用的方案，尚未等同于用户对最终视觉和动画效果的验收。

### 产品输入

首版只要求两项：

1. 一张用户授权的真人照片；
2. 一个用户选择的感觉/风格，例如纸感、毛毡、像素或插画，首版一次只选一种。

不要求用户准备三视图、动作参考图或多张照片。照片主体不清、遮挡严重或多人时，应明确提示重选，不静默生成一个不相关角色。

### 两层技术方案

**生产层：Skill + 多模态/编码大模型 + 生图模型。**

- Skill 是一套可执行的生产规范：输入检查 → 主体与特征提取 → 风格参数 → 角色母版 JSON → 部件/锚点/层级清单 → 动作语义模板 → 资产检查 → 失败重试。
- 多模态/编码大模型负责把照片和用户选定感觉转成可执行的角色资产规范、提示词和代码任务；它负责编排与检查，不等于生图模型。
- Seedream 负责把照片和规范转成角色母版、部件参考图和必要的动作参考图；真实接口效果尚未在此刻验证。

**运行层：本地角色资产 + 可复用 SVG/分层动作时间线。**

- 角色母版拆成身体、五官、眼睛、手、配饰、道具和背景/桌面等可控部件，统一画布、落点、层级和锚点。
- 呼吸、眨眼、轻摆等通用动作直接复用；喝水、挥手、击掌等接触动作使用动作语义模板，把角色部件接到手部和道具接口，不为每个角色整段重画。
- Electron 端本地播放 SVG/分层时间线；动作一次完成后停在末帧，失败回退静态母版。联网模型只发生在用户主动生产资产时，不发生在日常陪伴播放时。

这条路线吸收了 `6a33dfbb` 中“把 SVG 动画制作经验整理为 Skill”的方法，也保留当前项目已有的本地 SVG 单次播放基础。GIF 可以作为导出或对比格式，但不作为角色运行时的唯一资产；整段图生视频只用于复杂动作探索，不作为默认运行方案。

### 输出契约

每次“生成我的桌宠”输出一个可预览、可回退的角色包：

- `character-master`：透明母版、风格、身份锚点、比例、版本号；
- `character-parts`：身体/脸/眼睛/手/配饰等部件和层级；
- `motion-library`：至少待机呼吸、眨眼、挥手、喝水、击掌、睡觉 6 个动作示例；
- 每个动作：语义、时长、关键姿态、接触点、是否循环、完成末帧；
- `preview`：角色母版与动作示例的可操作预览；确认前不覆盖当前桌宠；
- `fallback`：静态角色和通用待机，确保生成失败仍可使用。

### 第一轮技术验收

用两张不同主体照片复用同一套动作模板，检查：

- 是否仍是同一角色：轮廓、脸、配饰和比例不漂移；
- 手与杯子/对方手掌是否真实接触；
- 动作是否连续，不是关键帧跳变或整张图晃动；
- 动作结束是否稳定停在自然末帧；
- 缩到桌面实际尺寸后，角色和动作是否仍可辨；
- 一个角色失败时是否只回退该动作，不破坏已确认的角色母版。

通过这轮之前，不批量生产 35 个动作，也不把小红书作者的动画效果写成此刻已经达到。

## 两个可比较的感觉

A 手绘纸感：纸张颗粒、色铅笔边缘、身体不完全对称，像绘本里的一小块日常。与用户先前给的洗漱参考图在“温和手作感 + 具体动作”上接近；不复制原图人物或猫。

B 羊毛毡：在相近角色与动作上增加纤维、柔软体积、微缩道具，像桌边真的有一个小玩偶。它用于比较材质偏好，不等于一定比手绘更可爱。

先问自己两件事：想看着它，还是想伸手摸它？希望它像一页绘本，还是一个真实的小摆件？不需要判断哪张“更高级”。可以混合偏好：“喜欢 A 的纸感和 B 的身体比例”。

## 推荐的制作顺序

1. **挑质感，不先批量生产。** 用当前 A/B 两图比较材质、轮廓、五官、道具接触。避免一次性让 AI 生成几百张，最后每张都是不同角色。
2. **建立唯一角色母版。** 选定后固定正面、3/4 侧面、侧面、背面，外加 3 个表情。记录头身比例、眼距、眼睛位置、叶芽数量与方向、手脚数量、颜色、材质、描边。此时场景简单、光线均匀，方便参考。
3. **把角色与场景分开管理。** 母版角色永久使用同一来源；场景可以是桌面、窗边、水槽等独立参考。明确哪个参考负责身份、哪个负责动作、哪个负责背景，不让三张参考互相争夺角色外观。
4. **一次只做一个动作。** 每个动作做准备、关键动作、完成三张关键帧。固定镜头、尺寸、角色落点、道具尺度；手接触道具，杯口到嘴边，布接触叶片，而不是整个画面漂移。
5. **静态验收后才动。** 在桌面实际 308 px 场景宽度看轮廓与动作；合格后再制作 2–4 秒短片或分层动画。每个成片有静态终帧，播放一次；用户点击新提醒才产生下一个动作。
6. **用动作编号配文案。** 文案生成时同时选择 motionId。已有相符动作就用，没有就保留静态或补做新动作，不能为了热闹把喝水配给洗杯子。

Runway 官方 References 文档支持“参考图固定主体、角色与场景分别迭代”的流程，也提醒变量越多越可能产生变化。本次只阅读其官方方法，没有登录、购买、上传你的收藏或调用该付费服务；也不把厂商的一致性描述当成百分百保证。

## 三条生产路径怎么选

| 路径 | 合适的阶段 | 优点 | 必须面对的限制 |
| --- | --- | --- | --- |
| 参考图生成关键帧 + 图生视频 | 探索高质感手绘/毛毡效果 | 容易得到材质和表演感 | 可能变脸、变道具、漂移镜头，需要逐条筛选；本版没调用视频生成 |
| 角色拆层 + 道具分层 + 局部动画 | 已确定形象且动作短 | 母版不换脸、体积小、播放次数可控 | 需准备眼睛、手、身体、道具的干净分层；转身等复杂动作仍需新增画稿 |
| 固定 3D 模型 + 骨骼与动作 | 明确选择立体风格且长期大量动作 | 几何身份固定、多角度复用 | 初始建模、材质、绑定成本更高；不宜在形象未定时投入 |

对目前《此刻》，推荐先用 A/B 确认方向，再以 6 个高频动作做完整质感样片：喝水、洗杯子、擦叶片、写字、合本、伸手放松。现有 35 个矢量动作先验证文案映射和单次播放；这不是以低质画面替代最终质感验收。

## 可直接复用的提示词

角色母版：

> 以提供的已选角色图为唯一身份参考。保留身体轮廓、五官位置、眼距、叶芽、短手脚、颜色与材质，画同一个角色的正面、3/4侧面、侧面、背面。中性表情，均匀柔和光线，背景简单，不加新装饰，不混合其他角色。不要美化成另一个角色。

动作静帧：

> 身份参考负责“是谁”，场景参考只负责背景。保持母版角色不变。动作是【擦一片叶子】：一只手扶住叶片，另一只手拿软布贴住叶面，姿态自然。固定桌面机位、角色尺度和落点，留足动作空间。不要浮空的手、穿透、额外手脚、文字或水印。

单次视频：

> 固定镜头，无推拉、摇移、切镜。完全沿用起始图中的角色身份、材质、道具、背景。角色只做一次【拿起杯子→杯口靠近嘴→放回杯垫】，总长约3秒；随后保持自然静止。只移动手臂和必要的身体部位，不让整张背景一起晃动。无循环、无多余动作、无物体融化或增减。

## 验收门槛

- 身份：每帧同一轮廓与叶芽、五官比例、手脚数量；不能仅“差不多像”。
- 接触：杯口、手、软布、笔与对象的位置有物理关系。
- 场景：角色不会缩放漂移；桌面和光源不跟动作晃动。
- 动作：能在不看标题时分清喝水/洗杯子/摆杯子；多个动作的文案优先展示第一步，不声称动画完整教会全部步骤。
- 静止：完成后不再循环；新卡、收起、减少动画能中断；失败回退静态。
- 文字：生成动作只做可视化，不承诺健康功效、不假装观察到用户行为。

技术实现：当前原型用本地 SVG 分层动作，时间线 `repeatCount=1`，3.2 秒结束，3.4 秒换成无动画静帧。应用不会下载或执行用户自带 SVG。相关规范：[SVG animateTransform](https://developer.mozilla.org/en-US/docs/Web/SVG/Reference/Element/animateTransform)、[repeatCount](https://developer.mozilla.org/en-US/docs/Web/SVG/Reference/Attribute/repeatCount)。
